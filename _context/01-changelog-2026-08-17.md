## 2. Structured data — `index.html` (fixes SCH-01, SCH-02, SCH-03, SCH-04 · was 0/100)

One `<script type="application/ld+json">` block before `</head>`, holding a single
`@graph` of six cross-linked nodes. Cross-linking by `@id` is what lets an engine resolve
all of it to one entity instead of four unrelated snippets.

| Node | `@id` | What it establishes |
| --- | --- | --- |
| `ProfessionalService` + `Organization` | `#business` | The company: name, legal name, phone, email, address, 10 areas served, `knowsAbout`, and a 5-item `hasOfferCatalog`. |
| `Person` | `#ryder` | Ryder as author and founder, `worksFor` the business. Authorship is a trust signal engines weigh when deciding whom to quote. |
| `WebSite` | `#website` | The site itself, published by `#business`. |
| `WebPage` + `AboutPage` | `#webpage` | The homepage, `about` the business, authored by `#ryder`. |
| `VideoObject` | `#reel` | The on-camera reel. Video content is otherwise completely invisible to AI. |
| `FAQPage` | `#faq` | All 10 existing Q&As, extracted verbatim from the page HTML. |

**Note:** the FAQ JSON-LD was generated by parsing the live `.faq-item` markup, so the
schema and the visible page cannot drift apart. If you edit an FAQ answer on the page,
update the matching `acceptedAnswer` too — mismatched schema is worse than none.

**Verify:** paste the page into `validator.schema.org` → zero errors. Then Google Rich
Results Test for the FAQ and Video eligibility.

- `<link rel="canonical" href="https://ryderschilling.com/">` — stops the wrong URL being
  indexed or cited.
- `<meta name="robots" content="index, follow, max-image-preview:large, max-snippet:-1, max-video-preview:-1">`
  — explicitly permits full-length snippets and large image previews in AI answers.
- `<meta name="author" content="Ryder Schilling">` — the author signal SCH-02 wanted.
- `geo.region` / `geo.placename` — US-FL, Santa Rosa Beach.
- Full Open Graph set (`og:type`, `og:site_name`, `og:locale`, `og:url`, `og:title`,
  `og:description`, `og:image` + dimensions + alt).
- Full Twitter/X card set (`summary_large_image`).
- `<link rel="alternate" type="text/markdown" href="/index.md">` and
  `<link rel="alternate" type="text/plain" href="/llms.txt">` — tells an agent there is a
  clean twin of this page it can read instead of wrestling with the HTML.

## 4. Single `<h1>` — `index.html` + `css/style.css` (fixes STR-01)

The desktop hero and the mobile hero were both `<h1>`, so the page shipped two. The mobile
one is now `<p class="m-hero-title">`; the desktop `.hero-title` stays the single `<h1>`.
Added `.m-hero-title { margin: 0; }` to `css/style.css` so the paragraph's default UA
margin can't shift the mobile layout.

**Why not the other way round:** the desktop hero is first in DOM order, which is what a
crawler reads regardless of which one CSS is hiding at a given breakpoint.

**Verified:** rendered both versions in headless Chromium at 390x844 and diffed the
geometry. `.m-hero-title` top/height, the eyebrow, the CTA row, and the `#work`,
`#services` and `#faq` section offsets are byte-identical, and document height is 10978px
in both. Zero layout movement. `grep -c '<h1' index.html` returns 1.

## 11. New file: `vercel.json` — security headers (fixes all 5 header findings)

| Header | Value |
| --- | --- |
| `Content-Security-Policy` | `default-src 'self'` base, with `connect-src` and `form-action` explicitly allowing `https://formsubmit.co` and `https://api.web3forms.com` |
| `X-Frame-Options` | `DENY` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | camera, microphone, geolocation, payment, usb, magnetometer, gyroscope all `()` |
| `Strict-Transport-Security` | `max-age=63072000; includeSubDomains; preload` |
| `Cross-Origin-Opener-Policy` | `same-origin` |

> WARNING: **The CSP allowlists the two form endpoints on purpose.** `js/main.js` posts the
> lead and gate forms to `formsubmit.co/ajax/` (line ~1141) and `api.web3forms.com/submit`
> (line ~1203). A `connect-src 'self'` CSP would have silently killed every form submission
> on the site — the form would still animate and "succeed" while the lead went nowhere.
> **If you ever change form providers, update the CSP in the same commit.**

> WARNING: **`script-src` keeps `'unsafe-inline'`** because Chrome enforces CSP against
> inline `<script type="application/ld+json">`, so a strict policy would block the
> structured data that is the whole point of this round. To tighten it later, hash the
> JSON-LD block and swap `'unsafe-inline'` for that hash — but the hash breaks on every
> schema edit, so only do it once the schema is stable.

Also in the same file: correct `Content-Type` for `llms.txt`, `llms-full.txt`, `index.md`,
`robots.txt`, and `sitemap.xml`, `Access-Control-Allow-Origin: *` on the three AI files so
agents can fetch them cross-origin, and a 1-year immutable cache on `/assets/*`.

**Verify (all five, after deploy):**
```
curl -sI https://ryderschilling.com/ | grep -i -E "content-security|x-frame|x-content-type|referrer-policy|permissions-policy"
```
